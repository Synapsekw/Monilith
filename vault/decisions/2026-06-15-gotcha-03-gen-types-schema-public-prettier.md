# Gotcha 03 — regenerate types with `--schema public | prettier` to match MCP output

## Context

`src/types/database.types.ts` is generated by the Supabase MCP `generate_typescript_types` tool.
A naive `supabase gen types typescript --linked > src/types/database.types.ts` does **not** reproduce
that file, so it shows up as spurious drift / churn even when the schema is unchanged.

## Decision

The canonical regeneration command (and the `pnpm db:types` script) is:

```
supabase gen types typescript --linked --schema public | prettier --parser typescript > src/types/database.types.ts
```

## Rationale

Diffing CLI output against the committed (MCP-generated) file revealed two differences:

1. **Schema scope** — raw CLI includes the `graphql_public` schema; the MCP tool emits `public` only.
   `--schema public` fixes this.
2. **Formatting** — the committed file is Prettier-formatted (trailing semicolons etc.); raw CLI output
   is not. Piping through `prettier --parser typescript` fixes this.

With both applied, CLI output matched the committed file byte-for-byte (0-line diff).

## Consequences

- Positive: `pnpm db:types` is a safe one-liner; no churn, regen-after-migration has no excuse.
- Negative: requires the Supabase CLI to be linked (`supabase link`) locally.
- Open follow-ups: no CI drift check (no local DB stack available; Branching overkill solo). A husky
  `pre-push` or secret-gated `--linked` CI job remain options if drift ever slips through.
