## 1. Pitch

**Monolith** is a cloud-native **"Work OS"** in the spirit of Monday.com — folding in the best of
ClickUp (nested hierarchy, docs, native time tracking) and Asana (goals/OKRs, workload, portfolios)
into one coherent product. Not a clone: the _ultimate_ version. Monday's visual, color-coded board
experience as the foundation; ClickUp's depth; Asana's polish. Design language: modern monochromatic
(neutral grayscale) with a single configurable accent, **dark-first** ("Monolith Keystone": layered near-black surfaces +
periwinkle accent; light supported but secondary), Linear-grade restraint applied to a colorful category.
Built on **Next.js 16 + React 19 + Tailwind v4 + Supabase**, multi-tenant (org-scoped RLS) from day one.

Master spec: [[2026-06-14-pulse-design]] (`docs/superpowers/specs/2026-06-14-pulse-design.md`).
Visual reskin target + prototype reuse map: [[2026-06-16-decision-08-dark-first-monday-reskin]].

- **The MCP OAuth server worked for exactly one client, and that hid two structural bugs** ([[2026-08-06-0902-mcp-oauth-loopback-and-bridge-secret]]). `claude.ai` registers one fixed https callback and is the only client it had ever seen, so (a) exact `redirect_uris.includes()` matching and (b) a Vault secret named `mcp_bridge:<userId>` both passed every test and four months of production. Connecting a CLI client exposed both: exact matching rejects any client that binds an **ephemeral loopback port**, which RFC 8252 §7.3 says a server MUST allow ([[2026-08-06-gotcha-76-exact-redirect-uri-matching-locks-out-every-cli-client]]); and a per-user secret name means the **first** bridge a user mints squats it forever, so no second client — and no MCP client alongside a personal agent — could ever connect ([[2026-08-06-gotcha-77-a-per-user-vault-secret-name-caps-a-user-at-one-bridge]]). The second surfaced as a **500 with an empty body**, diagnosable only from the Vercel runtime log; the token endpoint now returns the RFC 6749 §5.2 `server_error` envelope. Both verified live: two token rows with distinct bridges for one user.

- **A shipped verb is not a reachable verb.** `propose_move_item` passed three reviews and four green gates on 2026-08-03 and was **dead on arrival** — the owner hit it within the day. Its id had to come from `semantic_search_items`, which is entitlement-gated, returns `[]` on any error, and needs the embedding sweep to have indexed the item. `query_items` had `item.id` in hand and dropped it; `propose_set_item_fields` named **no** id source at all. - **`revalidatePath` was never the missing piece.** The recorded diagnosis for "an approved AI write is invisible until you reload" blamed its absence in `src/lib/boards/actions/item.ts`. That absence is **deliberate** — the board hydrates once via `initialData` + `staleTime: Infinity` and never refetches the RSC, so revalidation changes nothing on screen and costs 9 queries (the rule is written down at `src/lib/boards/actions/group.ts`). The fix was to finish a rollout the repo had already decided on ([[2026-06-17-gotcha-13-realtime-only-insert-needs-optimistic-echo]]): `executeAction` returns a transient `BoardEffect`, one hook folds it into the board's TanStack cache. Effects deliberately stay **out** of `ExecutionResult`, which is persisted into `ai_messages.tool_trace` and would replay stale rows onto the board on every thread reopen.
- **A repair that matches zero rows reports success** ([[2026-08-04-gotcha-75-a-zero-row-repair-reports-success]]). `apply_migration` mis-stamping is now **5 for 5** — it is routine, budget it. `reconcile-migration-version.sh`, the sanctioned fix, **used to** print `WHERE name = '<slug>'` while the row it targets stores the full stamped filename: the `UPDATE` touched nothing, exited 0, and looked repaired. Only `pnpm db:ledger-check` caught it. **Repaired 2026-08-04** — keyed on `version` alone with `RETURNING`, and STEP 4 makes `db:ledger-check` mandatory (see Owed — tooling). The generalisable lesson survives the fix: **a `WHERE` clause is an assumption, and an `UPDATE` that reports rows-affected nowhere cannot tell you the assumption was wrong.**
- **A CHECK cannot express "this board is in my org."** A CHECK cannot subquery and must be IMMUTABLE, so it is never re-evaluated when the referenced row changes. The coupling is a **composite FK** `(board_id, org_id) → boards (id, org_id)` — enforced for every role including `service_role`, which bypasses RLS but never a constraint ([[2026-08-04-decision-34-a-docked-thread-belongs-to-its-boards-org]]). Two details are load-bearing: `MATCH SIMPLE` keeps `board_id IS NULL` legal as a property of the constraint class rather than a line someone must remember, and the PG15+ **column-list** `ON DELETE SET NULL (board_id)` is required — the bare form nulls every referencing column including the `NOT NULL org_id`, breaking `purgeBoard`. It was reachable with **no attack**: the board page never reconciles the `pulse_active_org` cookie, and 8 DEV users hold multi-org membership.

## 4. Engineering guardrails (from spec §8)

- TS strict, no unjustified `any`, **Zod at every boundary**.
- **Server Components by default**; Client only when interactive; **Server Actions for mutations**.
- **RLS is the real security boundary** — never trust the client. Default deny on every table; policies key off `org_members` for `auth.uid()`; no cross-org access.
- `SUPABASE_SERVICE_ROLE_KEY` never reaches the browser.
- All schema via **versioned migrations** (never dashboard click-ops). After each migration: `generate_typescript_types` → `src/types/database.types.ts`, then run `get_advisors`.
- Every feature ships with at least basic tests. **No phase complete with failing tests or advisor warnings.** Small conventional-commit commits.
- This is **Next.js 16, not the version in training data** — read `node_modules/next/dist/docs/` before writing framework code (see `AGENTS.md`).
- **The production deployment runs the DEV database** (`hjqca…`), not the PROD project (`jzsyq…`), until the app is feature-complete. DEV therefore holds real live data — treat it with production care. [[2026-08-02-decision-32-production-runs-the-dev-database]]
