## 1. Pitch

**Monolith** is a cloud-native **"Work OS"** in the spirit of Monday.com — folding in the best of
ClickUp (nested hierarchy, docs, native time tracking) and Asana (goals/OKRs, workload, portfolios)
into one coherent product. Not a clone: the _ultimate_ version. Monday's visual, color-coded board
experience as the foundation; ClickUp's depth; Asana's polish. Design language: modern monochromatic
(neutral grayscale) with a single configurable accent, **dark-first** ("Monolith Keystone": layered near-black surfaces +
periwinkle accent; light supported but secondary), Linear-grade restraint applied to a colorful category.
Built on **Next.js 16 + React 19 + Tailwind v4 + Supabase**, multi-tenant (org-scoped RLS) from day one.

Master spec: [[2026-06-14-pulse-design]] (`docs/superpowers/specs/2026-06-14-pulse-design.md`).
Visual reskin target + prototype reuse map: [[2026-06-16-decision-08-dark-first-monday-reskin]].

- **A cross-tenant hole was caught by the whole-branch review, not by six scoped ones.** `createConversation` resolved `agentId` through RLS under the comment _"never accept an agent id on trust"_ — and twelve lines below accepted `boardId` on trust, with no trigger or CHECK downstream. Any authenticated user knowing a board's uuid could plant attacker-authored, unattributed content into another tenant's dock. The RLS suite proved exhaustively who may **read** `board_id`; nobody asked who may **write** it. Six per-task reviews each saw a diff that was correct in isolation. **Also promoted from a deferred minor on inspection:** `board_id` was `on delete cascade` and `purgeBoard` is an owner-only hard delete, so one user could permanently destroy another member's *private* threads — now `on delete set null`, which fails closed.
- **`propose_move_item` shipped, and would have shipped dead** ([[2026-08-04-gotcha-73-a-tool-description-is-untested-surface-and-can-ship-a-dead-verb]], merged `2b186ce4`). The AI can now move an item between groups — a gap found by using the dock the hour it landed. Three tasks, three approving reviews, four green gates, **4205 tests** — and the verb could never have been invoked once: its description told the model to get `group_id` from `get_board_overview`, and that snapshot had no groups at all. No test could catch it, because the defect lived between the code and the English sentence telling a model how to reach it. **A plan that adds a verb requiring ids must VERIFY a read tool emits those ids, not assert it** — the assertion ships verbatim into the model's prompt.
- **The spec named its own mitigation, and that mitigation had never executed** ([[2026-08-04-gotcha-74-a-mitigation-that-never-executes-is-not-a-mitigation]]). Phase 2 widened RLS on a live table holding private `/ask` history and cited `ai-conversations.rls.integration.test.ts` as the control. - **Agent run history shipped — the observability half of Personal Agents** ([[2026-08-02-0708-agent-run-history]]). A last-run pill on every roster row from **one** `distinct on` RPC, plus the last 50 runs on expand. **Stored status is not display status:** the endpoint claims its fire slot as `status = 'error'` before any spend, so a healthy in-flight run is indistinguishable from a failure on `status` alone — the claim sentinel now renders "In progress" while fresh and "Didn't finish" once stale, never "Failed". Rendering it verbatim would have cried wolf on every working agent every morning.
- **`bridge_secret_id` was client-writable, and RLS structurally could not fix it.** `user_agents_owner_all` is `for all`, so an owner patching their own row satisfies the policy. The containment is a **grant** — table-level INSERT/UPDATE revoked from `authenticated` and re-granted column by column. It mattered concretely: `user_agents_vault_cleanup` deletes whatever secret id the row names, so a writable column was a route to deleting **another user's** MCP OAuth secret. Pinned by a live-DEV test, because a policy-only test cannot see the difference.
- **The debt audit that started the day** found two more reachable-but-uncalled `"use server"` endpoints (`bulkDeleteItems`, `bulkPurgeItems` — one a bulk **hard delete**), eight untested server-action modules, and a migration-ledger gate that had not run for two sessions. **+107 net tests**, two endpoints closed, two contract bugs fixed.

## 4. Engineering guardrails (from spec §8)

- TS strict, no unjustified `any`, **Zod at every boundary**.
- **Server Components by default**; Client only when interactive; **Server Actions for mutations**.
- **RLS is the real security boundary** — never trust the client. Default deny on every table; policies key off `org_members` for `auth.uid()`; no cross-org access.
- `SUPABASE_SERVICE_ROLE_KEY` never reaches the browser.
- All schema via **versioned migrations** (never dashboard click-ops). After each migration: `generate_typescript_types` → `src/types/database.types.ts`, then run `get_advisors`.
- Every feature ships with at least basic tests. **No phase complete with failing tests or advisor warnings.** Small conventional-commit commits.
- This is **Next.js 16, not the version in training data** — read `node_modules/next/dist/docs/` before writing framework code (see `AGENTS.md`).
- **The production deployment runs the DEV database** (`hjqca…`), not the PROD project (`jzsyq…`), until the app is feature-complete. DEV therefore holds real live data — treat it with production care. [[2026-08-02-decision-32-production-runs-the-dev-database]]
