# Add Group Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user add a new group to a board from the Table view, landing directly in rename mode with an auto-incremented default name.

**Architecture:** Mirror the existing `addColumn`/`addItem` patch-on-success pattern — the `createGroup` Server Action returns the real created row, an optimistic mutation inserts it into the React Query `["board", boardId]` cache, and the idempotent realtime handler de-dupes the echo. A `+ Add group` button at the bottom of the board creates `Group N` and drops the new section into its existing inline-rename input.

**Tech Stack:** Next.js 16 (App Router, Server Actions), Supabase, TanStack Query, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-06-19-add-group-design.md`

/** Append a group; idempotent on id. Immutable. */
export function insertGroup(cache: BoardCache, group: CacheGroup): BoardCache {
  if (cache.groups.some((g) => g.id === group.id)) return cache;
  return { ...cache, groups: [...cache.groups, group] };
}
```

/**
 * Add a new group. Patch-on-success (mirrors addColumn): wait for the server
 * to return the real group row, then insert it into the cache. The Realtime
 * INSERT echo is idempotent via `insertGroup`.
 */
const addGroupMutation = useMutation<
  { group: CacheGroup },
  Error,
  { name: string },
  void
>({
  mutationFn: async (vars) => {
    const res = await createGroup({ boardId, name: vars.name });
    if (!res.ok) throw new Error(res.error);
    return res.data;
  },
  onSuccess: ({ group }) => {
    qc.setQueryData<BoardCache>(key, (prev) =>
      prev ? insertGroup(prev, group) : prev,
    );
  },
});
```
